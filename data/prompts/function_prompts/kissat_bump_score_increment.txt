## 1. FUNCTION CONTRACT

```c
void kissat_bump_score_increment (kissat *solver);
```

**Purpose:** Update `solver->scinc` — the global additive score increment used by VSIDS. Called once per conflict-analysis round, AFTER the analyzed variables have each had `scinc` added to their score. By growing `scinc` over time, more recent conflicts contribute larger bumps, which is what produces the classic VSIDS decay effect.

**Caller context:** Called from `bump_analyzed_variable_scores` at the end of conflict analysis, immediately after the per-variable bump loop. There is no return value.

## 5. CRITICAL RULES

### Required invariants
1. `solver->scinc` must remain strictly positive on exit.
2. `solver->scinc` should be monotonically non-decreasing across calls (or explicitly rescaled) — the heap relies on newer bumps being at least as large as older ones.
3. If `solver->scinc > MAX_SCORE` at any point, call `kissat_rescale_scores(solver)` before returning, otherwise subsequent bumps can overflow.
4. The decay ratio must stay in `(0, 0.5]`. Outside this range the factor `1/(1-decay)` is undefined or unstable; assert or clamp if you compute it dynamically.

### What NOT to do
1. **DO NOT invent solver fields** — only use fields documented above.
2. **DO NOT create `kissat_*` prefixed variables** — reserved for API functions.
3. **DO NOT modify the variable score heap directly** — variable scores are bumped in the caller, not here.
4. **DO NOT skip the MAX_SCORE / rescale check** — it is the only overflow guard.
5. **DO NOT set `scinc` to a value smaller than its previous value without calling `kissat_rescale_scores`** — this silently corrupts the decision heap.

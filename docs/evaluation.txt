# Evaluation Pipeline

This document describes how to run the SAT solver evaluation pipeline on Compute Canada (Digital Research Alliance) SLURM clusters.

## Prerequisites

### 1. Benchmark Setup

Create the benchmark directory and add CNF files:

```bash
mkdir -p data/benchmarks/satcomp2025
cp /path/to/your/cnfs/*.cnf data/benchmarks/satcomp2025/
```

### 2. Base Solver

Ensure the base solver is built:

```bash
cd solvers/base && ./configure && make -j4
```

### 3. Python Environment

The pipeline expects a Python virtual environment at `~/general/bin/activate`. Adjust `_get_activation_cmd()` in `evaluation.py` if your environment is elsewhere.

## SLURM Configuration

The pipeline uses the following defaults for Compute Canada:

| Parameter | Value | Description |
|-----------|-------|-------------|
| Account | `def-vganesh` | Compute Canada allocation |
| Memory | `4G` | Per-task memory |
| Wall Time | `01:30:00` | 90 minutes per task |
| Timeout | `5000s` | ~83 min solver timeout |
| Max Concurrent | `100` | Concurrent array tasks |
| Max Array Size | `1000` | Tasks per job array |
| PAR2 Penalty | `10000` | Score for timeout/error |

## Usage

### Dry-Run Mode

Always test with `--dry-run` first to verify SLURM commands without submitting:

```bash
# Single algorithm
python src/llmsat/pipelines/evaluation.py \
    --algorithm_id <ALGORITHM_ID> \
    --dry-run

# All algorithms in a generation tag
python src/llmsat/pipelines/evaluation.py \
    --run_all --generation_tag gemini_trial1 \
    --dry-run
```

### Build Only

Compile solvers without submitting evaluation jobs:

```bash
python src/llmsat/pipelines/evaluation.py \
    --run_all --generation_tag gemini_trial1 \
    --build-only
```

### Full Evaluation

#### Per-Algorithm Mode (Default)

Submits one job array per solver. Good for testing or small runs:

```bash
python src/llmsat/pipelines/evaluation.py \
    --run_all --generation_tag gemini_trial1
```

#### Batch Mode

Submits unified job arrays across all solvers. More efficient for large runs:

```bash
python src/llmsat/pipelines/evaluation.py \
    --run_all --generation_tag gemini_trial1 \
    --batch-mode
```

### Collect Results

After all SLURM jobs complete, collect PAR2 scores:

```bash
# All algorithms in a generation
python src/llmsat/pipelines/evaluation.py \
    --collect_all_results --generation_tag gemini_trial1

# Single algorithm/code pair
python src/llmsat/pipelines/evaluation.py \
    --collect_result --algorithm_id <ID> --code_id <ID>
```

## CLI Reference

```
usage: evaluation.py [-h] [--algorithm_id ALGORITHM_ID] [--code_id CODE_ID]
                     [--first_n FIRST_N] [--run_all] [--collect_result]
                     [--collect_all_results] [--generation_tag GENERATION_TAG]
                     [--build-only] [--dry-run] [--skip-build] [--timeout TIMEOUT]
                     [--max-concurrent MAX_CONCURRENT] [--batch-mode]

options:
  --algorithm_id ID      Single algorithm ID to evaluate
  --code_id ID           Single code ID (used with --collect_result)
  --first_n N            Only evaluate first N algorithms (for testing)
  --run_all              Evaluate all algorithms in generation tag
  --collect_result       Collect results for a single algorithm/code
  --collect_all_results  Collect results for all algorithms in generation tag
  --generation_tag TAG   Generation tag to evaluate
  --build-only           Build solvers but skip SLURM evaluation
  --dry-run, -n          Print SLURM commands without submitting
  --skip-build           Skip build step, assume solvers are already built
  --timeout SECONDS      Timeout per CNF in seconds (default: 5000)
  --max-concurrent N     Max concurrent SLURM tasks per array (default: 100)
  --batch-mode           Use batch submission mode (unified arrays)
```

## Workflow Examples

### Testing with a Small Subset

```bash
# Build and evaluate only first 2 algorithms
python src/llmsat/pipelines/evaluation.py \
    --run_all --generation_tag gemini_trial1 \
    --first_n 2 \
    --dry-run
```

### Full Production Run

```bash
# Step 1: Build all solvers first
python src/llmsat/pipelines/evaluation.py \
    --run_all --generation_tag gemini_trial1 \
    --build-only

# Step 2: Submit evaluations using pre-built solvers (skip rebuild)
python src/llmsat/pipelines/evaluation.py \
    --run_all --generation_tag gemini_trial1 \
    --batch-mode --skip-build

# Step 3: Monitor jobs
squeue -u $USER

# Step 4: After completion, collect results
python src/llmsat/pipelines/evaluation.py \
    --collect_all_results --generation_tag gemini_trial1
```

### Dry-Run with Pre-Built Solvers

Use `--skip-build` with `--dry-run` to preview SLURM commands without rebuilding:

```bash
python src/llmsat/pipelines/evaluation.py \
    --run_all --generation_tag gemini_trial1 \
    --dry-run --skip-build
```

## Output Structure

Results are stored in the solver result directory:

```
solvers/<generation_tag>/<algorithm_id>/code_<code_id>/results/
├── cnf_file_list.txt          # List of CNF files to evaluate
├── run_solver_array.sh        # SLURM wrapper script
├── slurm_array_*.log          # SLURM output logs
├── <cnf_name>.cnf.solving.log # Solver output per CNF
└── solving_times.json         # Collected PAR2 results
```

## PAR2 Scoring

- **Solved**: Actual solving time in seconds
- **Timeout/Error**: 10000 seconds (2x the 5000s timeout)
- **PAR2 Score**: Average of all instance times

## Troubleshooting

### Job Submission Fails

Check that:
1. You're on a login node with `sbatch` available
2. Your account (`def-vganesh`) is valid
3. SLURM isn't in maintenance mode

### Missing Results

If some CNFs are missing from results:
1. Check SLURM logs in the result directory
2. Look for `TIMEOUT`, `CANCELLED`, or error messages
3. Re-run evaluation (already-completed CNFs are skipped)

### Build Failures

Build logs are saved to:
```
solvers/<generation_tag>/<algorithm_id>/code_<code_id>.build.log
```
